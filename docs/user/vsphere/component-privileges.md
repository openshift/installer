# Candidate vSphere privilege matrix for component-scoped credentials

This is a review and human-test matrix for `platform.vsphere.credentialType: component-scoped`, **not a certified minimum role**. It is inferred from the vSphere API calls made by the installer and its vSphere consumers. The existing [shared-credential privilege guide](privileges.md) remains the reference for `global` credentials; its combined role must not simply be copied to every component account.

For **each configured vCenter**, check the privileges of the credentials actually delivered to each consumer. A privilege on one account does not satisfy a requirement for another account. Likewise, a privilege on one vSphere object does not imply a grant on another object unless the assignment propagates. All accounts require sufficient read/visibility access to discover the objects they use; test this through their actual inventory paths. `System.View` and `System.Read` are useful candidate privilege IDs, but a successful login alone does not demonstrate that inventory discovery works.

The identifiers below are vSphere privilege IDs, **not Kubernetes RBAC**. “Candidate” means the operation strongly suggests the privilege, but the exact vCenter-enforced minimum, source/destination assignment, or release-specific code path still needs a human test. “Conditional” means do not require it for installations that do not use that operation. In particular, never infer all `VirtualMachine.*` privileges from one clone or CNS call.

## Machine management (`machineManagement`)

This account is used by the installer, its destroyer, CAPV, and the in-cluster Machine API. The installer already checks many of these IDs against topology objects in `pkg/asset/installconfig/vsphere/validation.go`, using the groups in `pkg/asset/installconfig/vsphere/permissions.go`; that check does not prove the account covers every later CAPV, Machine API, or destroy operation.

| Source template or source VM | `VirtualMachine.Provisioning.DeployTemplate` **or** `VirtualMachine.Provisioning.Clone` | Clone from a template or a VM, respectively. Confirm source type; the importer creates a template if no template was supplied. [CAPV clone](https://github.com/kubernetes-sigs/cluster-api-provider-vsphere/blob/v1.14.0/pkg/services/govmomi/vcenter/clone.go#L319-L338). |

## Storage (`storage`)

**Both** the vSphere CSI driver and the OpenShift CSI operator use this component's credentials. Their needs must be combined **within this account**, not spread over the other component accounts.

| Consumer and vSphere object | Candidate privileges | Operation and condition |
| --- | --- | --- |
| CSI driver; vCenter CNS and storage-policy services | `Cns.Searchable`, `StorageProfile.View` | CNS volume queries and PBM policy lookup/compatibility. Policy use is configuration-dependent. [CSI test-role map](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/tests/e2e/config_secret_utils.go#L675-L684); [CNS queries](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/pkg/common/cns-lib/volume/manager.go#L2329-L2367); [PBM reads](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/pkg/common/cns-lib/vsphere/pbm.go#L94-L162). |
| CSI driver; eligible provisioning datastores | `Datastore.FileManagement`, `System.Read` | The driver explicitly tests **both** on datastores before admitting them for block-volume provisioning. Check each configured/eligible datastore that the cluster is expected to use, not every datastore on the vCenter. [Authorization check](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/pkg/csi/service/common/authmanager.go#L328-L383). |
| CSI driver; node VMs | `VirtualMachine.Config.AddExistingDisk`, `VirtualMachine.Config.AddRemoveDevice` | Candidate rights for block attach/detach via CNS; corroborated by CSI's test-role setup. Do **not** infer VM clone/power privileges from CNS attach. [CNS attach/detach](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/pkg/common/cns-lib/volume/manager.go#L1148-L1307); [role map](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/tests/e2e/config_secret_utils.go#L675-L684). |
| CSI driver; vSAN file-service compute cluster | `Host.Config.Storage` | **Conditional: vSAN file volumes.** The driver explicitly checks this privilege on compute-cluster entities. [Authorization check](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/pkg/csi/service/common/authmanager.go#L423-L495). |
| CSI operator; vCenter tagging service, tags, and tagged datastores | `InventoryService.Tagging.CreateCategory`, `EditCategory`, `CreateTag`, `EditTag`, `AttachTag`; candidate `InventoryService.Tagging.ObjectAttachable` on datastores | **Conditional: managed default StorageClass.** Create/update categories and tags and attach them to the relevant datastore(s); use existing objects' update paths when present. [Operator calls](https://github.com/openshift/vmware-vsphere-csi-driver-operator/blob/7568756078abec435912c45d185292d90574fb46/pkg/operator/storageclasscontroller/vmware.go#L272-L350); [managed gate](https://github.com/openshift/vmware-vsphere-csi-driver-operator/blob/7568756078abec435912c45d185292d90574fb46/pkg/operator/storageclasscontroller/storageclasscontroller.go#L144-L165). |
| CSI operator; vCenter storage-policy service | `StorageProfile.View`, `StorageProfile.Update` | **Conditional: managed default StorageClass.** Query/retrieve or create a PBM profile. Do not require policy **deletion** solely from a test-only call site. [Operator PBM calls](https://github.com/openshift/vmware-vsphere-csi-driver-operator/blob/7568756078abec435912c45d185292d90574fb46/pkg/operator/storageclasscontroller/vmware.go#L355-L427). |
| CSI driver/operator; VM, host, folder, datacenter, datastore, cluster topology | Read visibility (`System.View`/`System.Read` candidates) | Resolve nodes, placement, datastores, and tag ancestry. Validate the inventory scope and propagation separately from write privileges. [CSI topology reads](https://github.com/kubernetes-sigs/vsphere-csi-driver/blob/0f871ab/pkg/common/cns-lib/vsphere/virtualmachine.go#L220-L288). |

CNS **snapshot** operations are not evidence for `VirtualMachine.State.CreateSnapshot` or `VirtualMachine.State.RemoveSnapshot`; they call CNS snapshot APIs instead. Test snapshot-enabled configurations independently rather than adding VM snapshot IDs without an API basis.

## Cloud controller manager (`cloudControllerManager`)

| vSphere object | Candidate privileges | Operation and condition |
| --- | --- | --- |
| Node VMs and their ancestor folders, datacenters, hosts, resource pools, and datastore hierarchy | Read visibility, including `System.View`/`System.Read` where appropriate; upstream guidance recommends the **ReadOnly** role on parent entities | Find node VMs by UUID/IP/DNS and read VM properties. A login or read grant on only the vCenter root does not prove VM discovery. [Cloud-provider role guide](https://github.com/kubernetes/cloud-provider-vsphere/blob/cd8a5b039da08fd69959fba6f69994af6e2d4cbc/docs/book/vcp_roles.md#L15-L18); [VM search](https://github.com/kubernetes/cloud-provider-vsphere/blob/cd8a5b039da08fd69959fba6f69994af6e2d4cbc/pkg/common/connectionmanager/search.go#L123-L193). |
| Host/resource-pool/VM ancestry and associated tags | Read visibility of tag categories, tags, and object attachments | **Conditional: tag-based region/zone lookup.** REST `ListAttachedTags`, `GetTag`, `GetCategory`; no `AttachTag`, tag creation, or VM power/clone privilege follows from these reads. [Tag calls](https://github.com/kubernetes/cloud-provider-vsphere/blob/cd8a5b039da08fd69959fba6f69994af6e2d4cbc/pkg/common/connectionmanager/zones.go#L322-L383). |

NSX-T routes or load balancers, if configured, have separate NSX permissions; they are not additional vSphere privilege IDs in this matrix.

## vSphere Problem Detector (`vsphereProblemDetector`)

This section covers what the detector **uses to run diagnostics**. Its current `CheckAccountPermissions` instead checks the **detector's own session** against machine-installation privilege groups; those are *observations the detector attempts to make*, not proof that it needs VM-create or tag-write privileges to perform its diagnostics. A restricted detector account will produce misleading missing-machine-privilege reports until those checks are separated or redirected to the machine-management identity. [Session setup](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/operator/vsphere_check.go#L62-L86); [account check](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/check/permissions.go#L190-L239).

| vSphere object | Candidate privileges | Operation and condition |
| --- | --- | --- |
| Node VMs and inventory ancestors, hosts, datacenters, datastores | Read visibility (`System.View`/`System.Read` candidates) | Find VMs by provider-ID UUID; read VM, ESXi, datastore, cluster, and task properties. [Node properties](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/check/interface.go#L35-L48); [lookup](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/operator/vsphere_check.go#L334-L372). |
| Datastores checked for the failure domains | `Datastore.Browse` | Browser searches for `/` and `/kubevols`. **Current code suppresses an immediate `SearchDatastore` error**, so a passing diagnostic cannot by itself prove this right. [Browser call](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/check/folder.go#L20-L95). |
| vCenter PBM service | `StorageProfile.View` | **Conditional: StorageClass policy configured.** Query/retrieve profiles and inspect compatible datastores. No policy-update privilege follows from these reads. [PBM calls](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/check/datastore.go#L174-L197). |
| Node VMs, tasks and performance data; tagged topology objects | Read visibility (`System.View` candidate) | Task and performance queries and, when topology requires it, reading tag/category attachments and host-group configuration. [Task checks](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/check/tasks.go#L16-L39); [topology checks](https://github.com/openshift/vsphere-problem-detector/blob/14a2d33817c1ddd1d753cc76decea059376e30c9/pkg/check/zones.go#L180-L245). |

## Review and human-test checklist

- Use **different accounts** for all four components on each vCenter. Test wrong-password and wrong-scope cases as well as missing privilege IDs; do not log credentials or include them in error text.
- Check the identities *delivered* to CAPV, Machine API, CSI driver/operator, CCM, and Problem Detector. CAPV has its own `identityRef` Secret in addition to the four component Secrets in `pkg/asset/manifests/openshift.go`.
- Check each configured failure domain's actual template, VM folder or parent, resource pool (including default/root pool), compute cluster, network, datastore, and vCenter root. Cover multiple vCenters, inherited versus non-propagating roles, and unreadable objects; distinguish “not found” from “not visible.”
- Test optional paths separately: OVA import versus supplied template, created versus pre-existing folder, HostGroup affinity, managed versus unmanaged StorageClass, block versus vSAN file volumes, storage policy, tagging, snapshots, and destroy of cluster-owned volumes.
- Verify a restricted detector account can perform diagnostics without being required to hold machine-management write rights; fix or explicitly waive its existing self-privilege checks. Do not count successful calls made with `machineManagement` as verification of `storage`, `cloudControllerManager`, or `vsphereProblemDetector`.
- Pin the shipped versions of CAPV, Machine API, CSI driver/operator, CCM, and detector for the target release before making these candidates a hard installation gate. The links above span an installer CAPV v1.14.0 dependency and inspected upstream commits, not one verified release payload. Compare failures with vCenter API privilege requirements and record corrections in this matrix.
